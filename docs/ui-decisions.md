- 인박스별 등급 배정, 호출 통계, 대화 내용, 시각은 시안용으로 지은 값이다.
- 시안에는 샌드박스 4개가 모두 있는 것으로 그렸다. 첫 구현은 `public`과 `team`뿐이다 (D13).

### 2. U1: 메일형 3단

왼쪽부터 메뉴, 요청 목록, 본문 순서다. 앞선 시안이 대시보드처럼 보여서 메일 프로그램처럼 읽히는 구조로 바꿨다.

| 단 | 내용 |
|---|---|
| 메뉴 | 검색창(통합 질의 겸용), 결재함, 알림함, 인박스 목록, 대화 목록, 관리자 설정 |
| 요청 목록 | 고른 인박스의 요청. 탭은 전체, 결재 필요, 자동응답 |
| 본문 | 원본 화면과 결재 카드 |

인박스 화면에는 단을 더하지 않는다. 대화는 따로 열리는 대화창에서 한다 (U12).

문서 열람형과 메신저 스레드형 시안은 채택하지 않았다. 시안의 보관 페이지에 남겨 뒀다.

### 3. U2, U3: 인박스와 에이전트

요청은 메일처럼 보이지만 메일이 아니다. GitHub 이슈일 수도, Slack 메시지일 수도, 리서치 에이전트가 올린 결정 요청일 수도 있다.

| 인박스 | 들어오는 것 | 에이전트 | 등급 | 샌드박스 |
|---|---|---|---|---|
| GitHub 이슈 | 공개 레포의 질문 | `public-desk` | 공개 | `public` |
| 이메일 | 사외 문의 | `mail-desk` (가칭) | 공개 | `public` |
| Slack 문의 | 개인 메신저로 온 문의와 협업 요청 | `collab-desk` (가칭) | 회사 내 | `company` |
| 내 리서치 | 리서치 방향 결정 | `task-orbit` | 업무 내부 | `team` |

- 인박스 하나에 에이전트 하나가 기본이다.
- 인박스의 등급이 샌드박스를 정한다. 등급이 같은 인박스는 샌드박스를 같이 쓴다.
- 등급 배정은 시안용이다. 팀 확인이 필요하다.

### 4. U4, U5, U6: 응답과 결재

| 상태 | 뜻 |
|---|---|
| 자동응답 | 에이전트가 결재 없이 답함 |
| 결재 필요 | 사람이 범위를 정해야 함 |
| 결재 완료 | 결정이 끝남. 응답하지 않기로 한 것도 포함 |
| 차단됨 | 샌드박스가 에이전트의 시도를 막음 |

결재 카드는 질문 하나와 선택지 세 개 안팎으로 이뤄진다. 질문은 요청에 따라 다르다.

| 요청 | 질문 |
|---|---|
| 외부 질문 | 어디까지 공개할까요? |
| 협업 요청 | 어디까지 공유할까요? |
| 리서치 | 어느 방향으로 진행할까요? |

- 응답 전문과 요청 전문은 원할 때만 펼쳐 본다.
- 무엇을 고르든 빼는 항목은 카드에 따로 적는다.
- 결재함은 모든 인박스의 결재를 모아 보여 준다. 요청에서 결재로, 결재에서 요청으로 갈 수 있다.

### 5. U7: 요청 목록

- 왼쪽에 보낸이 아이콘을 둔다. 아이콘 안에 이름을 적고, 색과 작은 배지로 어느 채널에서 왔는지 나타낸다.
- 보낸이와 제목을 같은 굵기로 강조한다. 읽은 요청은 둘 다 옅게 한다.
- 제목은 문서 제목처럼 적는다. 말하듯 적지 않는다. 예: "PRISM 설계 문서 경로 문의", "ORBIT 벤치마크 진행 상황 문의". 말하듯 적는 글은 대화창에서만 쓴다 (U21).
- 상태 태그는 각 행의 오른쪽 열에 둔다. 폭을 고정해 세로로 정렬한다. 시각은 태그 아래에 둔다.
- 안 읽은 요청은 왼쪽에 세로 막대를 붙인다.

### 6. U8: 원본 화면

본문 자리에 요청이 들어온 화면을 그대로 보여 준다.

| 채널 | 원본 화면 |
|---|---|
| GitHub 이슈 | 이슈 화면 |
| Slack 문의 | 대화 화면 |
| 내 리서치 | 에이전트가 도는 터미널 |

- 읽기 전용이다.
- 에이전트의 답이 들어갈 자리를 원본 안에 표시한다.

구현할 때: GitHub와 Slack은 자기 화면을 다른 페이지 안에 넣지 못하게 막는다. API로 내용을 받아 직접 그려야 한다. 터미널은 세션 출력을 받아 그린다.

### 7. U9: 관리자 화면

| 화면 | 단위 | 볼 수 있는 것 | 바꿀 수 있는 것 |
|---|---|---|---|
| 에이전트 | 에이전트 | 컨텍스트 사용량과 구성, 호출 통계 | 불러오는 자료, 대화 압축, 기억 비우기, 시스템 프롬프트 |
| 샌드박스 | 샌드박스 | 지금 추론 경로, 등록된 제공자 | 추론 제공자와 모델, 컨텍스트 길이, 게이트웨이, 네트워크 정책 |

- 공개 등급이 아닌 샌드박스에서는 외부 추론 제공자를 고를 수 없다 (D2).
- 다른 구획의 자료는 불러오는 자료에 넣을 수 없다 (D1).
- 설정마다 바로 적용되는지, 샌드박스를 다시 만들어야 하는지 적는다.
- 지금 추론 경로가 설정과 같은지 표시한다. 게이트웨이 하나에 경로가 하나뿐이어서 어긋날 수 있다 (D3).

### 8. U10, U11: 차단 기록과 규칙

U10. 에이전트가 하려다 막힌 일을 요청 화면에 보여 준다. 원본에서 지시로 보이는 문장을 표시하고, 막힌 시도를 시간순으로 적는다. 사람은 그 요청을 어떻게 처리할지 고른다.

U11. 결재 카드에 "비슷한 요청에 이 결정을 규칙으로 쓰기"를 둔다. 규칙이 적용된 자동응답은 어느 결재에서 나온 규칙인지 목록에 적는다.

둘 다 해커톤의 차별점으로 넣었다. 실제로 검증한 차단은 승인 호출(`POST /reviews/*/approve`)이다 (D5).

### 9. U12, U22: 대화창

U12. 대화는 인박스와 따로 열리는 대화창에서 한다.

| 창 | 단 | 주인공 |
|---|---|---|
| 인박스 창 | 메뉴, 요청 목록, 본문 | 안건 |
| 대화창 | 담당자 목록, 대화, 오른쪽 패널 | 담당자 |

대화창을 여는 곳:

| 여는 곳 | 열리는 대화 |
|---|---|
| 요청 행에 마우스를 올리면 뜨는 말풍선 | 그 안건의 담당자. 오른쪽 패널에 그 안건 |
| 본문 제목 옆의 말풍선 | 위와 같음 |
| 메뉴의 인박스에 마우스를 올리면 뜨는 말풍선 | 그 인박스의 담당자 |
| 메뉴의 대화 목록 (U20) | 고른 담당자 |
| 검색창 (U14) | 통합 관리자 에이전트 |

- 요청 행과 인박스 항목은 마우스를 올렸을 때만 말풍선을 보여 준다. 요청 행에서는 시각이 있던 자리에 뜬다.
- 본문 제목 옆의 말풍선은 늘 보인다. 나눈 메시지가 있으면 개수를 함께 적는다.
- 대화창 왼쪽 아래의 "인박스 창으로"로 돌아간다.

대화창의 구성:

| 단 | 내용 |
|---|---|
| 왼쪽 | 담당자 목록(마지막 말, 시각, 안 읽은 수), 안건을 두고 나눈 대화 목록 |
| 가운데 | 고른 담당자와 주고받은 메시지, 입력창 |
| 오른쪽 패널 | 안건 하나를 두고 나누는 대화 (U22) |

U22. 대화창의 오른쪽 패널.

- 안건을 두고 대화할 때만 열린다. 닫으면 가운데가 넓어진다.
- 맨 위에 안건의 번호와 제목, 상태, "결재 카드 열기"가 있다.
- 그 아래에 담당자가 안건을 알린 메시지와 답글이 이어지고, 맨 아래에 답글 입력창이 있다.
- 담당자가 선택지를 새로 내면 패널에서 "결재 카드에 추가"를 누른다. 고르는 일은 인박스 창의 결재 카드에서 한다.

바꾼 것 (2026-09-27):

- 처음에는 본문에 "원본과 결재 / 대화" 탭을 뒀다. 대화로 바꾸면 원본과 결재 카드를 볼 수 없어서 뺐다.
- 다음에는 인박스 화면의 맨 오른쪽에 대화 패널을 넷째 단으로 끼워 넣었다. 결정과 다른 구성이어서 뺐다. 오른쪽 패널은 대화창 안에 있다. 인박스 화면은 3단이다.

### 10. U13, U18: 지시사항

인박스의 담당자에게 한 말이 여러 안건에 걸리면 에이전트가 해당하는 안건과 바뀌는 점을 먼저 보여 준다. 사람은 둘 중 하나를 고른다.

| 선택 | 결과 |
|---|---|
| 지시사항으로 저장 | 앞으로 들어오는 안건에도 적용 |
| 이번 안건에만 적용 | 지금 해당하는 안건에만 적용 |

- 저장한 지시사항은 대화창에서 그 담당자의 "지시사항" 탭에 모인다. 하나씩 끄고 켤 수 있다.
- 결재에서 나온 규칙(U11)도 같은 곳에 보인다. 지시사항은 말로 한 것이고, 규칙은 결재에서 고른 것이다.
- 지시사항은 에이전트의 컨텍스트에 들어간다. 관리자 화면의 컨텍스트 구성에 잡힌다.

U18. 저장 위치:

- 지시사항은 그 에이전트가 도는 샌드박스의 기억에 둔다.
- 샌드박스는 계속 돈다고 가정한다.
- 이번 안건에만 적용한 지시는 남기지 않아도 된다.
- 샌드박스를 다시 만들면 저장한 지시사항도 사라진다. 이 점은 받아들인다.

### 11. U14, U17, U19: 통합 질의

U14. 검색창에서 시작한다. 검색창에는 AI를 뜻하는 다이아몬드 표시를 둔다.

- 글자를 넣으면 아래에 두 가지가 뜬다: "요청에서 찾기"와 "통합 관리자에게 묻기".
- "통합 관리자에게 묻기"를 고르면 대화창이 열리고 통합 관리자 에이전트가 답한다.
- 메뉴에 통합 질의 항목을 따로 두지 않는다.

U17. 통합 질의는 통합 관리자 에이전트가 받는다.

| 에이전트 | 역할 | 답하는 범위 |
|---|---|---|
| 통합 관리자 에이전트 (head agent) | 모든 업무 에이전트가 하는 일을 알고, 통합 질의에 답함 | 통합 |
| 업무 에이전트 (subagent) | 인박스의 안건을 처리. 팀 단위로 둔다 | 안건, 인박스 |

- 에이전트를 처음 구성할 때 둔 `main`이다. `agents/team.yaml`에는 비서로 적혀 있다.
- 질문은 통합 관리자 에이전트에게만 간다. 업무 에이전트들의 일을 모아 답한다.
- 안건 하나나 인박스 하나를 두고 묻는 말은 그 인박스의 업무 에이전트가 답한다 (U12).

답의 구성:

- 맨 위에 정리를 둔다.
- 인박스마다 한 칸. 에이전트 이름, 등급, 관련 결재로 가는 링크를 함께 적는다.
- 해당하는 안건이 없는 인박스도 그렇다고 적는다.

U19. 통합 질의는 큰 모델로 돌린다고 가정한다. 어느 추론 제공자를 붙일지는 나중에 정한다.

바꾼 것 (2026-09-27): 처음에는 인박스마다 따로 묻고 화면에서 합치며, 정리는 가장 높은 등급의 샌드박스에서 로컬 모델로 만드는 안이었다. 통합 관리자 에이전트가 받는 구조로 바꿨다.

구현할 때 (제안):

- 통합 관리자 에이전트가 다른 샌드박스의 업무 에이전트에게 물을 때는 호스트 서비스 API를 거친다. `subagents.allowAgents`는 같은 샌드박스 안에서만 쓸 수 있다 (D4).
- 통합 관리자 에이전트의 프롬프트에는 모든 등급의 내용이 들어온다. 추론 제공자를 정할 때 D2와 함께 봐야 한다 (14절).

### 12. U15, U16: 대화의 한계와 기록

U15. 대화로 바꿀 수 없는 것:

| 항목 | 이유 |
|---|---|
| 결재를 대신하는 일 | 결재 경로는 에이전트가 호출할 수 없다 (D5) |
| 항상 빼는 항목 | 기밀 검토 기준이 정한다 (D10) |
| 샌드박스 정책과 추론 경로 | 관리자 화면에서만 바꾼다 (U9) |

대화의 등급 표시:

| 대화의 등급 | 입력창 위 문구 |
|---|---|
| 공개 | 적은 내용이 외부 추론 서비스로 나간다. 기밀은 적지 말 것 |
| 회사 내 이상 | 로컬 추론. 이 PC 밖으로 나가지 않음 |

목표 구조를 기준으로 적었다. 해커톤 시연에서는 모든 샌드박스가 외부 API로 추론하므로 문구도 그에 맞춘다.

U16. 대화 기록은 채팅 기록처럼 남긴다.

- 담당자와 나눈 메시지가 날짜 구분선과 함께 그대로 남는다 (U21).
- 안건을 두고 나눈 말은 그 안건의 스레드에 남는다.
- 따로 기록 화면을 두지 않는다.

### 13. U20, U21: 대화

U20. 메뉴의 인박스 아래에 "대화"를 둔다. 에이전트마다 한 줄이다.

| 화면에 적는 이름 | 에이전트 | 맡은 일 |
|---|---|---|
| 통합 관리자 에이전트 | `main` | 통합 질의 (U17) |
| GitHub 이슈 대응 에이전트 | `public-desk` | GitHub 이슈 인박스 |
| 리서치 에이전트 | `task-orbit` | 내 리서치 인박스 |
| Slack 문의 대응 에이전트 | `collab-desk` (가칭) | Slack 문의 인박스 |
| 이메일 대응 에이전트 | `mail-desk` (가칭) | 이메일 인박스 |

U21. 대화는 메신저처럼 그린다.

| | 인박스 | 대화 |
|---|---|---|
| 주인공 | 안건 | 담당자 |
| 목록에 보이는 것 | 보낸이, 제목, 상태 | 담당자의 이름, 접속 상태, 안 읽은 수 |
| 가운데 | 제목이 달린 요청 목록 | 담당자와 주고받은 메시지가 한 줄로 이어짐 |
| 안건을 다룰 때 | 본문에 원본 화면과 결재 카드 | 메시지에 안건 카드가 붙고, 거기서 스레드가 갈라짐 |

메신저에서 가져온 것:

- 메뉴의 대화 목록: 네모 아바타, 접속 상태 점, 안 읽은 수
- 위쪽: 담당자 이름과 상태, 탭(메시지, 지시사항, 맡은 안건)
- 메시지: 날짜 구분선, 네모 아바타, 이름과 시각
- 입력창: 서식 도구 줄, 안건 붙이기, 보내기
- 스레드: 메시지에서 갈라져 맨 오른쪽 패널에 열림

Slack의 색과 로고는 가져오지 않았다. 구조만 가져오고 색과 글꼴은 이 화면의 것을 쓴다.

안건을 두고 대화할 때:

- 담당자가 안건을 알리는 메시지에 안건 카드가 붙는다. 그 아래에 "답글 2개"가 달린다.
- 답글을 누르면 대화창의 오른쪽 패널이 열린다 (U22).
- 인박스 창에서 말풍선을 누르면 대화창이 열리고, 오른쪽 패널에 그 안건이 열려 있다 (U12).
- 결재는 결재 카드에서만 한다 (U15).

통합 관리자 에이전트와의 대화는 가운데에서 한다. 답에는 담당자별 요약과 관련 결재로 가는 링크가 붙는다.

바꾼 것 (2026-09-27):

- 처음에는 가운데 목록에 제목이 달린 대화들을 나열했다. 인박스와 같은 모양이라 담당자와 이야기하는 느낌이 나지 않아 메시지가 이어지는 구조로 바꿨다.

### 14. 확인이 필요한 것

| 항목 | 누가 | 내용 |
|---|---|---|
| 인박스별 등급 | 팀 | 3절의 배정이 맞는지. Slack 문의가 회사 내인지 사업부 내인지 |
| 인박스와 에이전트의 수 | 팀 | 인박스 하나에 에이전트를 둘 이상 둘 일이 있는지 |
| 통합 관리자 에이전트의 추론 제공자 | 다영 | 프롬프트에 기밀 등급의 내용이 들어온다. 목표 구조에서 외부 제공자를 붙이면 D2와 어긋난다. 큰 로컬 모델, 사내 추론 서버, D2의 예외 가운데 하나를 골라야 한다 |
| 통합 관리자 에이전트가 도는 샌드박스 | 다영 | `team`에 두면 공개 등급 인박스의 일은 호스트 서비스로 받아야 한다 |
| 팀 단위의 뜻 | 다영 | 업무(팀) 하나에 업무 에이전트 하나인지, 팀 하나에 샌드박스 하나인지 |
| 공개 등급 대화의 입력 | 팀 | 경고 문구로 충분한지, 보내기 전에 기밀 검토를 거칠지 |
| 규칙과 지시사항의 우선순위 | 팀 | 둘이 어긋날 때 어느 쪽을 따를지 |
| 원본 화면 | 다영 | GitHub 하나만 실제로 연결하고 나머지는 고정 화면으로 둘지 |
| 대화 기록의 저장 위치 | 팀 | 기밀 등급의 대화 기록을 어디에 둘지. 등급이 다른 담당자를 한 목록에 보여 줘도 되는지 |
| 대화창을 여는 방식 | 다영 | 별도의 창으로 띄울지, 같은 창에서 화면을 바꿀지. 시안은 어느 쪽으로도 읽힌다 |
| 에이전트의 화면 이름 | 팀 | 13절의 이름이 맞는지 |
