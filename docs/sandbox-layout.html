RFA 샌드박스 배치

샌드박스는 기밀 등급마다 하나씩 두고 이름도 등급을 따른다. 샌드박스끼리는 직접 말하지 않고 호스트 서비스의 API로만 주고받는다. 승인과 게시는 호스트에만 있다.

해커톤 시연에서는 모든 샌드박스가 외부 API로 추론한다. 그래서 시연에는 합성 자료만 넣는다. 점선으로 그린 것은 아직 없다.

시연 구성과 목표 구조

OpenShell은 gateway 하나에 추론 경로를 하나만 둔다. 같은 gateway의 샌드박스들은 그 경로를 같이 쓴다. 등급마다 다른 제공자를 쓰려면 gateway를 나눠야 하는데, 시연에서는 나누지 않고 모두 외부 API를 쓴다.

아직 확인하지 못한 것

  • 샌드박스 두 개를 한 gateway에. public과 team을 같이 띄웠을 때의 메모리와, 서로의 파일과 경로에 닿지 못하는지.
  • 기밀 검토의 위치. 지금 구현은 기밀 검토가 외부 대응 쪽에서 돈다. team으로 옮기려면 RFA_module과 knowledge API가 함께 바뀌어야 한다. 팀 확인 전이다.
  • 걸러낸 답변을 넘기는 방식. 샌드박스는 밖으로 요청을 보낼 수만 있다. team이 호스트에 밀어 넣을지, 호스트가 team의 에이전트를 부를지 정하지 않았다.
  • 모델 호출 방식. 샌드박스의 inference.local은 OpenAI 방식만 받는다. 워크플로는 Anthropic 방식을 쓴다.
  • 외부 API의 한도. 무료 한도(분당 약 40회)를 두 샌드박스가 같이 쓴다. 워크플로 한 번에 모델을 여러 번 부른다.
  • 도구 이름과 도구 거부의 실제 동작. 명단은 검증기를 통과했지만 샌드박스에 구워 확인하지 않았다.
