외부 Q&A와 공개 문서를 준비할 때 내부 지식은 필요하다. Boundary Desk는 자료 접근, 공개 판단, 발신 권한을 분리해 유용한 답변과 검토 가능한 경계를 함께 제공하는 제품 가설이다.

01 · problem & wedge

업무는 같고, 발신 대상만 다르다

담당자는 내부 자료를 확인하면서 외부용 문장을 쓴다. 문제는 어떤 자료를 읽었느냐뿐 아니라 그 내용이 어떤 문장과 채널을 통해 나가느냐다.

USE CASE A · Q&A

고객의 SDK 지원 문의

  1. 공개 자료: 현재 지원 범위와 출처 확인
  2. 내부 자료: 미공개 이슈와 출시 일정 대조
  3. 결과: 공개 사실만 답변, 일정은 보류
USE CASE B · 문서 게시

공개 Confluence 사용 가이드

  1. 공개 자료: 승인된 가이드와 코드 예제 수집
  2. 내부 자료: 기술 정확성 검토
  3. 결과: 최종 문장과 실제 대상 범위 승인 후 게시

사용자 가치

질문에 빠르게 답하고 작성 시간을 줄인다. 사용자는 어떤 근거로 발신했는지 재확인할 수 있다.

관리자 가치

에이전트별 파일, 네트워크, MCP, 모델 권한과 발신 승인을 분리해 검토할 수 있다.

투자 관점의 진입점

범용 에이전트 플랫폼보다 기술지원·문서팀의 외부 커뮤니케이션에서 먼저 가치를 증명한다.

02 · bird view

아키텍처: 읽기 권한과 발신 권한이 만나는 지점

아래 구성은 역할별로 독립된 OpenShell 샌드박스를 만든다는 설계안이다. 하나의 샌드박스 안에 여러 하위 에이전트를 배치하는 것만으로 같은 격리 효과가 생기지는 않는다.

03 · information policy

정보 등급은 파일 위치와 발신 규칙에 모두 적용

같은 문서라도 실제 공개 승인 여부와 대상에 따라 취급이 달라진다. 아래 등급은 프로젝트 제안 정책이며 회사의 공식 분류 체계를 대체하지 않는다.

등급을 내리는 작업은 모델의 “안전해 보인다”는 판단만으로 수행하지 않는다. 공개 원본 URL, 담당자 승인, 게시 대상 범위를 확인한다. 게시 승인 전에는 첨부파일·이미지·메타데이터도 같은 등급으로 취급한다.

샌드박스마다 다르게 잠글 것

자료 접근

허용 경로만 마운트/접근. 내부 문서는 내부 에이전트에서 읽기 전용으로 제공한다.

통신과 모델

네트워크 목적지, MCP 메서드·도구, 추론 제공자 경로를 에이전트별로 제한한다.

행동과 기억

외부 발신 권한은 별도 주체에만. 세션 기록·메모리·임시 파일·알림도 등급을 넘지 않게 관리한다.

06 · notifications & observability

알림은 결과를 알려주는 관찰 기능이고, 발신 승인은 별도 행동이다. 완료·승인 대기·정책 차단·발신 실패를 구분해 보여준다.

알림 노출 규칙

알림에는 업무 ID, 안전한 제목, 상태, 시각, 다음 행동만 쓴다. 내부 원문·개인정보·토큰·미공개 사실은 넣지 않는다.

사용자가 상세를 열 때 다시 권한을 확인한다. 외부 푸시는 더 짧은 메타데이터만 사용한다.

07 · technical defensibility

보안 기술을 다섯 경계로 설명

엔진이 막는 행위와 애플리케이션이 판단해야 할 내용을 구분한다. 핵심 차별점은 샌드박스 자체보다 권한을 넘는 데이터의 계약, 검증, 증거다.

01 · EXECUTION

실행 격리

별도 OpenShell 샌드박스에 실행 주체를 둔다. 파일 접근, 프로세스, 네트워크 정책을 각기 설정한다.

02 · TOOL / CREDENTIAL

MCP와 자격 증명

필요한 서버·메서드·도구만 노출하고 최소 권한 토큰을 사용한다. 지원되는 관리형 MCP 연결은 자격 증명을 샌드박스 밖에 둔다.

03 · INFERENCE

모델 경계

내부 자료가 외부 추론 서비스로 흘러가지 않도록 내부 에이전트의 모델 경로와 네트워크를 함께 설계한다.

04 · DECLASSIFICATION

공개 승인

분류 단계와 발신 단계 사이에 별도 검증을 둔다. 자동 공개 판정은 근거 목록에 묶고, 불명확한 문장은 담당자가 검토한다.

05 · AUDIT / RESPONSE

활동과 영수증

요청 ID, 승인 본문 해시, 대상, 정책 버전, 차단 이유와 발신 결과를 연결한다. 로그 원문을 알림으로 복사하지 않는다.

DESIGN CHOICE

최소 권한 관리자

라우터에는 내부 원문·게시 자격 증명을 함께 주지 않는다. 정책 변경과 발신 권한은 작업 에이전트가 아닌 별도 운영 주체가 관리한다.

09 · commercial lens

구매자는 누구이며, 무엇에 비용을 지불할까?

시장 규모나 가격을 근거 없이 단정하지 않는다. 아래는 팀 인터뷰로 검증할 고객·과금 가설이다.

WEDGE

기술지원·개발자 관계팀

반복 질문에 내부 자료가 필요하지만 외부 답변을 직접 작성하는 팀. 정확성과 발신 검토 시간을 함께 개선한다.

BUYER

지원 운영 책임자 + 보안팀

운영팀은 답변 속도·품질을, 보안팀은 접근 범위·승인과 감사를 검토한다. 두 집단의 조건이 모두 맞아야 도입된다.

MONETIZATION · 가설

워크스페이스 + 연결 채널

팀 단위 구독, 연결되는 업무 채널 수, 별도 감사·정책 운영 기능으로 확장하는 가격 가설을 검증한다.
